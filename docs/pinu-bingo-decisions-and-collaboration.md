# Pinu Bingo 决策与协作沉淀

更新日期：2026-06-29

本文用于沉淀 Pinu Bingo Challenge 已讨论过的产品判断、规则边界、评审风险和协作方式。后续评审、补 PRD、画流程图或继续开发前，优先阅读本文，再进入具体需求文档。

## 1. 当前定位

Bingo Challenge 第一版更适合定位为「每日词汇挑战 / 轻复习玩法」，而不是每个 Unit 的必经复习环节，也不是独立大型游戏模式。

核心判断：

- 它承接主线学习后的轻量复习和每日任务，目标是提高学习后的再次触达、短局爽感和任务完成动力。
- 它不应阻断主线学习能量进度。如果每个 Unit 都强制使用 Bingo 复习，容易变成重复负担。
- 它可以承接投放或首次体验用户，但这部分应使用「试玩模式」，不计入正式学习正确率、掌握度或 XP 核心判断。

## 2. MVP 边界

第一版建议做：

- 首页或任务页的轻量入口。
- 试玩模式：用于首次体验、投放承接、无词库用户体验玩法。
- 挑战模式：只使用用户已学词库，作为每日任务或轻复习。
- 4x4 / 5x5 棋盘自适应。
- 横线、竖线、斜线 Bingo，不包含四角 Bingo。
- 局内 Bingo 按钮、Fever 能量条、基础得分和结算。
- 首次进入完整局内教学引导，后续可从帮助入口再次查看。
- 基础埋点：入口曝光、开局、完局、正确率、Bingo 达成、Fever 触发、重复游玩。

第一版建议不做：

- 每个 Unit 强制 Bingo 复习。
- 排行榜、多人对战、金币下注、赛季活动等复杂外层。
- filler / safe mask 这类用未学词补局的机制。
- 服务端逐事件复算和复杂防作弊。
- 后台复杂调参平台。
- 四角 Bingo 玩法。

## 3. 入口策略

推荐优先级：

1. 任务页 / Daily Challenge 入口：路径稳定，最符合「每日挑战」定位。
2. 首页轻量卡片：可提升曝光，但应避免打断主线学习。
3. 独立浮窗：曝光最强，但弹出时机难控制，容易造成打扰，MVP 不建议作为主入口。
4. Unit 复习环节：路径可控，但如果每个 Unit 都出现，会卡学习节奏，也容易让玩法疲劳。

评审时建议明确：Bingo 不是主线强制学习节点，而是主线外的挑战任务。

## 4. 词库与抽题规则

最小可行规则：

- 只从用户已学 Unit 中抽题。
- 从最近完成的 Unit 开始，按完成时间倒序向前补足词量。
- 抽题前过滤不适合局内展示或 TTS 播放的词，例如过长词、重复答案、明显歧义词、缺少音频或 TTS 不可用词。
- 可用词数量不少于 24 时开启 5x5。
- 可用词数量不少于 16 且少于 24 时开启 4x4。
- 可用词数量少于 16 时不开放正式挑战，提示用户继续学习更多词。

后续可增强：

- 近 3 局出现过的词降权，减少重复疲劳。
- 最近 Unit 词占比更高，旧词少量混入，用于巩固。
- 错题、低掌握词提高权重，但不能让整局过难。

## 5. 目标分与 XP

目标分不是满分，也不是排行榜分数，而是「一个正常完成本局挑战的用户应达到的基准分」。

建议口径：

```text
target_score = round(target_valid_clicks * target_avg_click_score + target_bingo_count * target_avg_bingo_score)
```

默认值：

| 棋盘 | 目标有效点击 | 目标 Bingo 次数 | 目标分 |
|---|---:|---:|---:|
| 4x4 | 12 | 1 | 900 |
| 5x5 | 18 | 2 | 1500 |

解释：

- 目标有效点击用于衡量用户是否认真完成听辨，不要求点满全局。
- 目标 Bingo 次数用于衡量是否达成玩法核心。
- Fever 不纳入基础目标分，作为冲击更高 XP 档的奖励空间。
- XP 建议按「实际得分 / 目标分」分档，而不是按绝对分数硬切。

## 6. 局内教学引导

教学引导用于帮助首次进入 Bingo 的用户理解核心操作，不作为单独学习环节，不计入答题正确率。

触发：

- 用户首次进入 Bingo 时展示完整教学。
- 后续再次进入不强制展示，可通过局内帮助入口查看图片式教学。

教学内容：

- 标题使用 `How to Play`。
- 第一张卡片说明 Horizontal Line。
- 第二张卡片说明 Vertical Line。
- 第三张卡片说明 Diagonal Line。
- 第四张卡片只展示 Fever 区和 Bingo 按钮，不再展示棋盘。

表达原则：

- Pinu 是教学产品，教学图中应使用词卡，不建议用纯数字棋盘。
- 视觉应贴合 Pinu：浅蓝、白底、圆形词卡、清晰阴影、黄色可点击 Bingo 按钮。
- 不展示四角 Bingo，避免用户误解规则。
- 教学期间不计时、不出正式题、不产生答题事件。

## 8. 评审风险

需要在评审前主动说明的问题：

- 入口策略：如果定位为每日挑战，应避免把它做成每个 Unit 的强制复习。
- 学 / 练命名：建议将「学」改成「试玩模式」，否则容易被理解成正式学习路径。
- 词量不足：不要用未学词强行补局，MVP 应选择不开正式挑战。
- XP 边界：Bingo 可以奖励活跃和复习，但不能替代 Mastery。
- 教学图：必须避免四角 Bingo、纯数字棋盘和与 Pinu UI 不一致的配色。
- 服务端范围：MVP 应先记录结果和关键事件，不做复杂逐事件复算。

## 9. 已使用的协作方式

这轮工作主要经历了以下流程：

1. 先判断产品定位：Bingo 是每日挑战，而不是强制 Unit 复习。
2. 再严格评审需求：指出前后逻辑冲突、MVP 边界过大、词库和 XP 规则不清。
3. 补 PRD 缺口：目标分定义、局内教学引导、词库抽题规则。
4. 图表化流程：入口分流、局内状态、目标分结算、棋盘选择、教学引导。
5. 视觉化教学：基于 Pinu UI 生成 How to Play 图文教学方案。
6. 最后沉淀项目文档：把散落讨论变成可复用的评审入口。

本轮用到的能力：

- `product-management`：用于产品定位、PRD 评审、范围收敛和跨部门视角分析。
- `documentation`：用于把讨论结论沉淀为长期可维护文档。
- `computer-use`：用于查看在线文档现状，发现目标分和教学引导等缺口。
- 本地文件阅读与检查：用于对齐 `Pinu_game` 当前 demo、文档和 UI 表达。
- draw.io 文件生成：用于替代难复制的 Mermaid，产出可插入在线文档的流程图素材。

## 10. 后续协作优化

建议以后每个功能讨论都按这个结构沉淀：

- 先写「本期做什么 / 不做什么 / 待决策什么」。
- 每个规则都补齐 5 个视角：产品目的、用户体验、教研边界、UI 表达、研发实现。
- 流程图先确认信息结构，再生成图片或 draw.io，避免反复返工。
- 视觉稿先确认文案和布局，再追求细节风格。
- 在线文档中尽量使用 PNG 或 draw.io 源文件，不直接粘贴复杂 Mermaid。
- 每次交付都注明源文件、导出文件和建议插入位置。
